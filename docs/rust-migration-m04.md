# M04 — Git, fichiers, processus et agents

## Détection des manifestes — candidat après `c819fd0`

`infrastructure/launch_detection.rs` porte `lib/launch-detection.mjs` sans lancer les commandes détectées. Les lectures réutilisent `CheckedFile` et les dossiers ouverts de `cap-std`. Limites historiques : profondeur trois, 300 dossiers visités, 1 Mio par fichier, dossiers exclus, héritage npm/pnpm/yarn. Les scripts Vite/Next/Angular conservent les arguments de port ; les commandes composées perdent la détection automatique. Les profils .NET exposent noms, type et origines HTTP(S), jamais leurs variables d'environnement. Les profils invalides restent visibles et non sélectionnables.

Le tri utilise ICU4X, cantonné à `atelier-app`, pour conserver le classement linguistique de `localeCompare`, avec départage lexical des équivalents canoniques. Les caractères autorisés .NET et les espaces ECMAScript sont portés par `regex`, déjà présent transitivement ; aucun de ces adaptateurs n'entre dans core ou WASM. Versions et données ICU sont verrouillées dans Cargo.lock. L'API `Collator::try_new`/`compare_utf16` a été confrontée aux sources locales exactes de `icu_collator 2.4.0`. Le pré-tri lexical POSIX provient de [`uv__fs_scandir_sort`](https://github.com/libuv/libuv/blob/v1.x/src/unix/fs.c). Les variantes de locale et les noms de fichiers non Unicode restent à qualifier sur les systèmes ciblés ; le succès d'une locale Windows ne vaut pas preuve universelle.

`cargo xtask test-project-lifecycle-parity` compare désormais aussi onze arborescences temporaires avec le véritable scanner Node : gestionnaires, frameworks, dépendances, profils, types JSON inhabituels, ordre Unicode, limites, UTF-8 invalide et liens. Les attentes natives sont calculées par Node sur le même système, sans changer les références métier figées. Les tests Rust ordinaires vérifient les commandes exactes, profils UTF-16 et l'absence de valeurs privées. La route prototype reste limitée aux dépôts synthétiques décrits dans M03, avec test de refus des chemins externes et jonctions Windows.

Validation attendue sur GitHub Windows ; aucun test, compilation ou navigateur local. Les scénarios Linux/macOS sont préparés mais reportés à la qualification finale. M04 reste ouvert : Git/worktrees, inspection/diffs, ports/serveurs, diagnostics et exécution des agents, interactions, quotas et gestion des CLI ne sont pas qualifiés par ce scanner.
