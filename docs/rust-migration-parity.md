# Matrice de parité de la migration Rust

Référence : `843d3ea`, Atelier `0.1.9`, Node `24.22.1`, données version 2. Inventaire établi le 23 octobre 2026. Les ajouts M00 ne modifient pas le comportement applicatif. Le plan était non suivi au début de M00 ; aucune autre modification utilisateur n'était présente.

## Lecture et statut

Cette matrice décrit les contrats à conserver et leurs erreurs, pas seulement une liste de fichiers à traduire. L'[inventaire généré](rust-migration-inventory.md) complète chaque ligne avec **tous** les fichiers applicatifs, ressources, exemples, tests/supports, imports/appelants statiques, exports de compatibilité, noms de scénarios et repères de contrats. Une entrée sans appelant statique n'est pas du code mort : routes, injection, scripts natifs, assets et chargements de connecteurs sont aussi des entrées.

Dans les tableaux, les sources sans préfixe sont sous `lib/` et les noms de tests désignent `test/<nom>.test.mjs`. Les équivalents Rust indiquent les destinations de migration ; leur qualification complète reste **à faire**, avec les preuves partielles M01 ci-dessous. « Node » désigne une preuve de référence dans les tests existants ; les exclusions de plateforme et de livraison figurent dans le relevé d'exécution. Les tests de structure et les doubles ne sont pas des preuves natives ou E2E.

Après chaque incrément, remplacer « à faire » par les tests Rust précis, le résultat, le commit et les limites. Aucune suppression d'un test Node avant preuve équivalente de ses scénarios d'erreur. La couverture des fichiers est exhaustive ; les cas dynamiques sont décrits ci-dessous et les scénarios complémentaires exigés par le plan restent à implémenter dans leur lot.

## Contrats transversaux à ne pas perdre

- **Routes/méthodes** : l'inventaire capture `server.mjs` et chaque module HTTP, notamment les tables calculées de `card-workflow-routes`. Conserver routes Jira historiques, `/api/brainstorms`, changements de fournisseur, réponses agents et query `after`/`untracked`. Codes usuels 400/401/403/404/405/409/413, JSON `{ error }`, limites de corps et formes invalides font partie de la comparaison. Les erreurs spécifiques sont définies dans chaque route/cas d'usage ; ne pas remplacer les tests par un simple inventaire d'URL.
- **Événements** : `/api/events` exige la session ; `retry: 1000`, `connected`, `changed` regroupé sur 75 ms, heartbeat 15 s. Un client lent est déconnecté puis recharge état/journaux. Journal SQLite : `seq, runId, stream, text`, pages de 500, texte limité à 65 536 unités JS ; journal de run limité à 5 Mio en entrée et notification de troncature. Tester Unicode avant de remplacer une limite UTF-16 par une limite d'octets Rust.
- **Formats locaux** : `kanban.sqlite` + WAL/SHM ; tables `projects/cards/runs/settings/time_entries/logs/token_vault`. Noms backups `atelier-<epoch13>-<uuid>.sqlite`. `local-session` DPAPI/0600 ; `local-browser.html` privé POSIX ; `installation.json`; `release.json`; `.update-lock.json`; `.updates/update-*/{config.json,transaction.json,ready,previous,failed}` ; `update-result.json`, logs serveur et worker. Les descripteurs, permissions et fichiers temporaires font partie du contrat.
- **Stockage navigateur** : `atelier-session` dans localStorage et sessionStorage ; `atelier-language` ; `atelier-draft:<clé>` ; `atelier-brainstorm-page`, `atelier-brainstorm-draft:<session>`, `atelier-brainstorm-questions:<session>`. Les clés, leur contenu et le retrait du fragment secret doivent être comparés. Filtres actuellement en mémoire/URL : ne pas inventer une persistance nouvelle.
- **CLI/env** : `--stop`, `--no-browser`, `--import-data <source>`, worker `<stage> --recover` ; arguments de packaging/signature/checks. PORT et variables JIRA/AZURE/TEMPO, profils CODEX/CLAUDE, chemins OS, variables privées de launcher/worker/tray et options CI sont repérées par source dans l'inventaire, sans enregistrer leurs valeurs réelles. Les objets d'environnement filtrés et références calculées sont à relire, pas seulement les accès `process.env.X`.
- **Entrées non statiques** : `lib/connectors/*.mjs`, `connectors/*/index.mjs`, catalogues de langues, modules servis par liste blanche, commandes utilisateur configurées, injections de `createApp`, helpers natifs et hooks gestionnaire de paquets. Les callbacks de connecteurs ne doivent pas devenir des accès bruts à SQLite.
- **Nouvelles garanties** : verrou données commun M02/N1, identité de processus renforcée et fautes à chaque étape M09. Elles n'existent pas intégralement dans N0 ; conserver la référence et ajouter les preuves, sans prétendre à une parité déjà acquise.

## Fixtures et isolation

`test/fixtures/migration-data.mjs` fournit 10 projets, 500 cartes, 100 runs terminés, 200 temps draft et 10 000 lignes alternant stdout/stderr ; dates, identifiants et texte Unicode fixes. Les documents comprennent champs inconnus, null explicite et champ absent. Aucun chemin de dépôt utilisateur, URL de service ou jeton. Les projets ont volontairement un repo vide : ce corpus mesure le tableau, pas les worktrees ni les associations de projets (couverts par les fixtures Git existantes).

`rust-migration-reference` prouve la réouverture, le snapshot avec WAL, les curseurs et la conservation des documents après modification. Il **ne prouve pas encore** le passage Rust. `migration-agent.mjs` est un CLI local produisant un résultat protocolaire et un diagnostic séparé. Les scénarios crash, cancellation, interactions et processus descendants réutilisent les doubles déjà présents dans `agent-interactions`, `agent-provider-security`, `dev-servers`, `verification` et `worktrees` ; leurs cas d'erreur doivent être conservés.

Le benchmark lance le vrai `createApp` sur loopback avec ces données temporaires. La configuration neutralise les secrets d'environnement et les mises à jour distantes. Le navigateur utilise un profil temporaire, sans profil personnel. Les répertoires/processus temporaires sont nettoyés, y compris en cas d'échec.
