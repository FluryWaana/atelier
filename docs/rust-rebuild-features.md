# Reconstruction Rust — couverture fonctionnelle

Ce document suit les fonctions du nouveau produit, sans imposer les formats ou API Node. Décision du propriétaire : application préproduction, mêmes fonctionnalités améliorées, aucune rétrocompatibilité. Voir le [plan actif](rust-migration-plan.md).

Une fonction est terminée lorsque son cas d'usage, son écran, ses erreurs et ses tests de parcours sont livrés. Les briques du prototype ci-dessous sont réutilisables ; aucune ligne n'est encore déclarée complètement qualifiée. Les sources citées sont des repères, complétés par l'inventaire des sources et le README historique.

## Points de contrôle

- [`5be6ea9`, parcours Edge réussi](https://github.com/FluryWaana/atelier/actions/runs/40122863049), journal relu et capture du tableau inspectée : création/édition/déplacement sans agent, filtrage, confirmation de fermeture, erreur sans perte du brouillon, duplication/archives/restauration/suppression, redémarrage/session et gestion des projets jusqu'au retrait avec conservation des fichiers passent. L'échec natif restant concerne la préparation JSON du nouveau test de renommage (`from_value` incompatible avec le document brut) ; les tests renommage et statut utilisent désormais le même décodage texte que HTTP. Les critères/dépendances et le nouveau format SQLite sont postérieurs à cette preuve.

- Critères/dépendances candidats : maximum 20 critères de 500 unités, validation humaine, sélection des prérequis avec contrôle des cycles côté serveur. Parcours Edge étendu : conservation après redémarrage, critères non cochés dans la copie, dépendances non recopiées et refus de supprimer une tâche référencée. Résultats à recueillir.

- Format Rust candidat : identité SQLite `ATKR`, version `1`, initialisation transactionnelle uniquement sur fichier vide. Ouverture, restauration et transfert refusent les anciens formats, les identités étrangères et les versions futures. Tests synthétiques ajoutés pour la conservation octet pour octet des bases refusées, la réouverture, l'absence de restauration et de destination publiée. Les anciens comparateurs de stockage Node nécessitent désormais le checkout archivé ; ils ne constituent plus une commande de qualification de cette branche.
- CI de `a7e1c34` : deux échecs identifiés dans les journaux et corrigés avant le push suivant. Le build WASM exigeait le type explicite de l'événement `cancel` des dialogues. Le test HTTP conservait une ancienne assertion `todo` après la nouvelle assertion `doing` ; cette contradiction a été retirée, sans supprimer le contrôle de persistance. Aucun parcours enrichi n'est encore déclaré réussi.

- Candidat projets : le renommage auparavant ignoré est désormais validé et enregistré. Son ancien vecteur d'absence d'effet est remplacé par des contrôles du nom et de la conservation des réglages/dépôts. Le parcours Edge prépare création, renommage, branche/consignes, refus d'un dépôt en double sans perte du brouillon, création d'une tâche dans le projet sélectionné et retrait/archivage sans suppression du dossier. Aucun dossier utilisateur n'est utilisé.
- Tableau `dd69aae` : [contrôles natifs Windows réussis](https://github.com/FluryWaana/atelier/actions/runs/40121728616), journal relu (Clippy natif/WASM, Rust et DPAPI). Le parcours navigateur échouait pendant la création de sa fixture, car `standby` n'est pas accepté comme statut initial. Préparation corrigée par `1b020c9` en utilisant `review` ; la CI du parcours enrichi reste à recueillir.

- R01, changement de contrat intentionnel : déplacer manuellement une carte vers « En cours » enregistre son statut sans lancer d'agent. Le lancement aura une action explicite en R03. Les anciens vecteurs d'autolancement sont remplacés par un test de toutes les transitions manuelles, avec refus si tâche occupée/archivée, et un parcours HTTP/navigateur vérifiant l'absence d'exécution. Les autres vecteurs de validation restent actifs. Le parcours navigateur conserve Unicode valide, échappement HTML, persistance et rotation de session ; la conservation d'unités UTF-16 isolées n'est plus un contrat de l'interface reconstruite.
- Candidat R01 : le parcours Edge couvre cinq colonnes, recherche dans les descriptions, filtre projet/archives, édition dans une colonne et changement de colonne, confirmation de fermeture du brouillon, erreur serveur sans perte de saisie, duplication, archivage/restauration et suppression avec annulation. Résultats distants à recueillir avant validation. Les brouillons affichent un avertissement à la fermeture/recharge ; ils ne survivent pas encore à une fermeture forcée du navigateur.
