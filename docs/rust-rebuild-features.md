# Reconstruction Rust — couverture fonctionnelle

Ce document suit les fonctions du nouveau produit, sans imposer les formats ou API Node. Décision du propriétaire : application préproduction, mêmes fonctionnalités améliorées, aucune rétrocompatibilité. Voir le [plan actif](rust-migration-plan.md).

Une fonction est terminée lorsque son cas d'usage, son écran, ses erreurs et ses tests de parcours sont livrés. Les briques du prototype ci-dessous sont réutilisables ; aucune ligne n'est encore déclarée complètement qualifiée. Les sources citées sont des repères, complétés par l'inventaire des sources et le README historique.

Point candidat connecteurs : paramètres en cinq onglets conservant leurs panneaux/brouillons, installation native approuvée en deux étapes, champs typés/coffre, contrôles/actions de lecture datés et retrait confirmé raccordés à l’interface bilingue. Recherche paginée et import confirmé de 1–20 tickets par page, identité scoped tenant/module, projet/rapport figés et création atomique sans écrasement des cartes existantes raccordés. Scénarios purs/SQLite/navigateur synthétiques écrits pour invalidation d’approbation, secret non relu, brouillon inter-onglets, conflit conservé, rollback/retry/scopes, rechargement, import et retrait conservant la carte ; couverture de traduction étendue à tous les fichiers Rust de l’interface. **Non compilé/non exécuté**, formatage seulement ; aucun nouveau résultat ni validation R04/R06/R07. Rafraîchissement/écritures/reprise des modules et POSIX restent ouverts ; détails dans [le contrat des connecteurs](rust-connectors.md).

Point candidat lanceur : commandes natives launch/stop/serve, réutilisation de la preuve de session loopback et vérification du dossier, lancement en arrière-plan, arrêt via annulation existante, sélection des chemins portables/installés des trois OS et ouverture native du navigateur raccordés. Le service produit refuse les assets legacy. Scénarios synthétiques de parsing/ports/démarrage/redémarrage/persistance et refus avant initialisation écrits, **non compilés/non exécutés**. Tray, vrais installeurs/paquets et update/rollback restent ouverts ; voir [le suivi du lanceur](rust-launcher.md). R06/R07 non validés.

Point candidat archives : validateur de payload partagé dans atelier-app, création ZIP Rust sans remplacement et extraction privée avec bornes/chemins/types/CRC/SHA/cible, commandes xtask et scénarios synthétiques des cinq architectures écrits. **Aucun build/test/archivage exécuté, aucun artefact réel** ; signature, installateurs, récupération, avis de licences complets et qualification restent ouverts. Voir [les paquets Rust](rust-packages.md).

Suite candidate : signature Ed25519 et préparation authentifiée de paquets avec confiance synthétique externe, taille/empreinte, cible et version strictement supérieure vérifiées avant lecture/extraction. Générateur/signataire de fixtures et scénarios de falsification/clé étrangère/downgrade/remplacement écrits seulement ; **aucune clé générée, aucun paquet signé ni test exécuté sur ce PC**. Ce point remplace la mention de signature entièrement absente du point précédent, sans valider R06/R07.

Cycle R06 candidat raccordé : installation CLI sans écrasement, confiance stockée séparément, versions signées et lanceur stable, aperçu/confirmation, worker détaché, contrôle de la version réellement démarrée, rollback de code et reprise au lancement. Données jamais restaurées/supprimées par le retour de code ; changements humains d’identité/pointeur/contenu refusés. Interface bilingue au sixième onglet, brouillons protégés et commandes ambiguës sans renvoi automatique. Scénarios Rust aux frontières de reprise, scénario CI entre deux vrais binaires à compiler et WebDriver négatif écrits ; **tous non compilés/non exécutés, aucun artefact réel**. Wrappers Setup/DEB/RPM, désinstallation, tray, avis complets de licences, autres parcours et POSIX restent ouverts. Statuts exacts dans [les paquets Rust](rust-packages.md).
