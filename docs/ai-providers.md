# Fournisseurs IA

Dans **Paramètres → Fournisseurs IA**, ajoutez ou configurez des profils. Le choix est disponible dans les réglages généraux, par projet, dans les tâches et dans le brainstorming. Les profils Codex et Claude existants sont conservés sans migration des cartes.

Cliquez sur un fournisseur dans **Vos agents** ou dans les paramètres pour ouvrir sa fiche : compte, abonnement, capacité restante et installation. Les liens **Voir l’utilisation** et **Gérer l’abonnement** ouvrent le site officiel, avec la session de votre navigateur (qui peut être différente du compte CLI).

Pour Codex connecté à ChatGPT, la fiche utilise les lectures officielles [`account/read` et `account/rateLimits/read`](https://learn.chatgpt.com/docs/app-server) du CLI. Elle affiche les fenêtres renvoyées par le service, leur pourcentage restant et leur prochaine réinitialisation. Aucun prompt ni appel de modèle n’est lancé. Les lectures sont limitées à dix secondes et 1 Mio de sortie, puis le processus est arrêté ; les résultats publics sont conservés en mémoire pendant une minute. Une fenêtre déjà expirée affiche « À actualiser » plutôt qu’un ancien pourcentage.

Pour Claude, l’abonnement est affiché si `claude auth status` le communique. Les quotas sont lus sur `https://api.anthropic.com/api/oauth/usage`, avec le jeton d’accès OAuth du profil CLI sélectionné : `CLAUDE_CODE_OAUTH_TOKEN`, ou `.credentials.json` dans `CLAUDE_CONFIG_DIR` (par défaut `~/.claude`). C’est le mécanisme utilisé notamment par [Headroom pour Windows](https://github.com/tesuheee/headroom-ai-usage-monitor/blob/master/src/UsageClients.cs). Les fenêtres de 5 heures, de 7 jours et les limites par modèle sont affichées lorsqu’elles existent. Aucun jeton de renouvellement n’est utilisé et aucun fichier de connexion n’est modifié : en cas d’expiration, reconnectez Claude Code.

Cette interface d’usage Anthropic n’est pas documentée publiquement et peut changer. La destination HTTPS est fixe, les redirections sont refusées, les réponses sont limitées à 64 Kio et dix secondes. Les jetons ne sont ni renvoyés au navigateur, ni copiés dans les réglages ou les journaux. Les profils partageant le même jeton partagent un cache en mémoire de cinq minutes ; une réponse 429 suspend les requêtes au moins jusqu’au `Retry-After` annoncé (quinze minutes par défaut). Ce délai n’est pas conservé après un redémarrage. Les connexions disponibles uniquement dans le trousseau macOS ne sont pas lues par cet adaptateur.

Le lien vers [l’utilisation Claude](https://claude.ai/settings/usage) et la commande officielle [`/usage`](https://code.claude.com/docs/en/costs) restent accessibles. Les profils API renvoient vers la consommation et la facturation API, distinctes des abonnements. Une donnée absente reste « non communiquée » et n’est jamais remplacée par 0 % ou 100 %.

- **Codex CLI** et **Claude Code CLI** : nom, exécutable facultatif, modèle et niveau de réflexion. Un dossier de configuration absolu permet d’utiliser une connexion existante distincte (`CODEX_HOME` ou `CLAUDE_CONFIG_DIR`). L’application ne lance pas de connexion interactive.
- **Codex avec clé API** : le CLI reste nécessaire pour travailler dans le dépôt. La clé est enregistrée dans le coffre système existant et transmise uniquement au processus via `CODEX_API_KEY`, jamais dans les arguments ou les réglages publics. L’état « clé configurée » ne valide ni la clé ni le crédit disponible. Voir la [documentation officielle](https://learn.chatgpt.com/docs/non-interactive-mode#authenticate-in-automation).
- **CLI personnalisé** : choisissez un exécutable et des listes JSON d’arguments distinctes pour analyser et modifier. `{model}` et `{effort}` sont remplacés dans chaque argument. Le prompt arrive sur stdin ; stdout devient le compte rendu final (limité à 100 000 caractères). Utilisez un CLI non interactif qui applique lui-même les permissions de chaque mode. Aucun shell intermédiaire n’est lancé. Sous Windows, fournissez un `.exe` ou l’exécutable de l’interpréteur avec le script en argument, plutôt qu’un wrapper `.cmd`.

Pour un CLI personnalisé, la commande de version doit écrire sa version sur stdout. La commande de compte facultative doit retourner un JSON avec `loggedIn` (booléen), `email` et `authMethod` (chaînes facultatives). `[]` désactive cette vérification. Le libellé du compte est une note personnelle, distincte de l’identité détectée. Les secrets ne doivent pas être placés dans les arguments.

La détection affiche la version installée et le compte communiqué par le CLI. Codex peut communiquer son identité via son cache de connexion ; si celle-ci est uniquement dans le trousseau, l’interface signale qu’elle n’est pas disponible. Aucun jeton de connexion n’est renvoyé au navigateur. Les fichiers de connexion Codex et Claude sont lus avec une limite de 64 Kio ; les fichiers spéciaux, les chemins réseau (y compris les séparateurs Windows mélangés) et les liens sortant du profil sélectionné sont refusés.

Les exécutables personnalisés, y compris les chemins substitués à Codex ou Claude, ne sont jamais lancés automatiquement pour ce diagnostic : utilisez **Vérifier les installations**. Cette action exécute leurs commandes de version et de compte avec les droits de votre session. Le résultat est conservé jusqu’à une modification des profils ou au redémarrage. Les commandes de version ne reçoivent pas les clés API dans leur environnement.

Les dernières versions stables de Codex et Claude sont consultées dans le registre npm officiel. Un CLI personnalisé peut renseigner le nom de son paquet npm. La vérification utilise un cache d’une heure et un délai réseau de cinq secondes et une limite de réponse de 64 Kio ; elle ne transmet aucune clé API. Les versions plus anciennes sont signalées, les préversions sont distinguées, et l’absence de réseau ou d’une version comparable donne « Vérification de mise à jour indisponible ». Cette comparaison concerne la dernière version stable publiée, pas un éventuel canal de déploiement différé du CLI. Aucune installation ni mise à jour automatique n’est effectuée.

Le bouton **Mettre à jour le CLI** est proposé pour les installations natives détectées dans `~/.local/bin` ou `~/.local/share/codex|claude`. Après confirmation, Atelier lance uniquement la commande officielle [`claude update`](https://code.claude.com/docs/en/setup#update-manually) ou [`codex update`](https://learn.chatgpt.com/docs/developer-commands), sans shell ni clé API transmise. Les exécutables personnalisés et les installations gérées par un autre outil restent à mettre à jour avec leur gestionnaire habituel. Aucune mise à jour n’est lancée en arrière-plan sans action de votre part.

Une barre animée affiche les étapes de vérification, d’installation et de contrôle de la version. Elle n’affiche pas de pourcentage : les CLI ne fournissent pas de progression chiffrée fiable. Le canal et les restrictions configurés dans le CLI sont conservés ; la commande peut donc terminer sans atteindre la dernière version publiée. Atelier vérifie la version réellement active avant d’annoncer un succès. L’opération est limitée à trois minutes, sans restauration automatique de l’ancienne version. Les lancements d’agents, les diagnostics, les modifications de profils et les restaurations de sauvegardes sont bloqués pendant l’opération. Une restauration est également refusée pendant une lecture de compte. Fermez également vos sessions CLI extérieures à Atelier, que l’application ne contrôle pas.

Un profil utilisé par une tâche (y compris archivée), un projet ou le choix global ne peut pas être supprimé. Changez d’abord ces références. L’historique des exécutions conserve le nom et le type utilisés. Les modifications de profils sont bloquées pendant les exécutions actives. Le type d’un profil est fixe ; créez un autre profil pour changer de protocole.

Les processus reçoivent une liste limitée de variables système et les identifiants de leur propre fournisseur. Les autres secrets du serveur, variables d’injection de code et réglages de proxy ne sont pas hérités. Un CLI nécessitant ces variables supplémentaires peut donc demander une adaptation. La recherche des exécutables ignore le répertoire courant et les entrées relatives du PATH ; les chemins réseau et périphériques sont refusés dans les profils. Sous Windows, seuls les exécutables locaux `.exe` et `.com` sont acceptés. Les secrets connus sont masqués dans les sorties ; une ligne dépassant 1 Mio est entièrement masquée pour éviter une fuite à la jonction de deux fragments.

Ces protections ne constituent pas une isolation du système d’exploitation. Un CLI s’exécute avec les droits de votre compte et peut accéder à ses fichiers : n’ajoutez que des programmes de confiance. Les permissions d’analyse et de modification d’un CLI personnalisé relèvent de ce programme. Le masquage des sorties n’empêche pas un programme malveillant d’encoder ou d’envoyer des données ; aucune garantie de sécurité à 100 % n’est possible.
